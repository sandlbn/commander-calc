\chapter{Working with Files}
\label{ch:files}

A \ccprod{} workbook is saved in its own format, \fname{.X16S}, which holds
everything: every worksheet, every cell, the formulas as you wrote them, the
number formats, the column widths and the worksheet names. Nothing is lost in a
save and nothing is lost in a load.

The commands that read and write other programs' files --- \menupath{Import}
and \menupath{Export} --- are in Chapter~\ref{ch:importexport}. This chapter is about your own work.

\section{The file commands}

\begin{cctable}{Command}{Key}{2.2in}{2.62in}
\menupath{File > New} & \key{F1} \\
\menupath{File > Open} & \key{F3} \\
\menupath{File > Save} & \key{F4} \\
\menupath{File > Save as} & \key{F6} \\
\end{cctable}

\section{Starting a new workbook}
\index{New command}

\key{F1} throws away what is in memory and gives you one empty worksheet.

If the workbook has been modified, \ccprod{} asks \msg{discard unsaved
changes?} first, under the title \msg{New workbook}. \key{Y} means yes; any
other key means no.

\section{Saving}
\index{saving}

\key{F4} saves. If the workbook already has a name it is written straight back
under that name, with no dialogue and no confirmation. If it does not --- a
workbook you started from \menupath{New}, or one that came from an import ---
you are asked for a name first.

\key{F6}, \menupath{Save as}, always asks for a name.

The name field takes a name up to twenty-three characters long. Type it, edit it
with the same keys you use in a cell, and press \key{Return}. \key{Esc}
cancels --- and so does pressing \key{Return} on an empty field.

\begin{ccnote}
\menupath{Save} always writes the native \fname{.X16S} format, whatever the name
you give it. The hint about \fname{.XLSX} and \fname{.CSV} on that dialogue
belongs to \menupath{Export}, which shares the same box. A workbook saved as
\fname{ACCOUNTS.XLSX} from \menupath{Save} is a \fname{.X16S} file with a
misleading name; Excel will not open it and \ccprod{} will.
\end{ccnote}

\subsection{Saving is safe}
\index{saving!atomic}

\ccprod{} never writes over your previous workbook until the new one is
complete and verified. A save goes:

\begin{ccprocedure}[What a save actually does]
\item Write the whole workbook to a temporary file, \fname{CMDRCALC.TMP}.
\item Read it back and check its checksum.
\item Only then delete the old file and rename the temporary one into its
place.
\end{ccprocedure}

If anything fails --- a full card, a bad sector, the power going off --- the
temporary file is removed and your previous workbook is still there, whole. The
cost is that a save needs room on the card for two copies of the workbook at
once.

\key{$\uparrow$} and \key{$\downarrow$} move the selection, \key{Return} opens
the file, \key{Esc} cancels. With the mouse, the first click on a line selects
it and a second click on the same line opens it; a click anywhere off the list
cancels.

If the workbook in memory has been modified you are asked \msg{discard unsaved
changes?} before the list appears.

\subsection{Directories}
\index{directories}\index{opening a workbook!subdirectories}

\textbf{A name beginning with \lit{/} is a directory, not a file.} Select one
and press \key{Return} and the list shows what is inside it; the title row
changes to say where you are.

Directories are listed above the files, and \lit{/..} --- the way back to the
directory above --- is always the first entry when there is one. At the
directory \ccprod{} started in the title row reads \lit{.} and there is no
\lit{/..}, because that is as far up as the dialogue goes.

\begin{cctable}{To}{Do this}{2.2in}{2.62in}
Go into a directory & Select \lit{/NAME} and press \key{Return} \\
Come back out & Select \lit{/..} and press \key{Return} \\
Open a workbook & Select it and press \key{Return} \\
\end{cctable}

Opening a workbook from a subdirectory works exactly as it does from the
starting one: the path travels with the name, and the workbook's name on the
tab line shows where it came from.

\begin{ccnote}
The dialogue only ever goes \emph{down} from the directory \ccprod{} started
in. There is no way to reach a directory beside or above it, and the path it
can build is limited to 47 characters --- a directory nested deeper than that
cannot be entered.

If a directory will not open --- because the card was changed, or the name is
no longer there --- \ccprod{} says \msg{cannot open that directory} and stays
where it was.
\end{ccnote}

\subsection{Long lists}

The list holds at most \textbf{sixty-four} entries and shows sixteen at a time,
scrolling as the selection moves. A \lit{\^{}} at the top right of the list
means there is more above; a \lit{v} at the bottom right means there is more
below.

Entries are sorted, so a workbook is where you would expect to find it.

\begin{cccaution}
A directory holding more than sixty-four entries is listed as far as the
sixty-fourth and no further, with nothing said about what was left out.
Directories count towards that total. Keep workbooks in directories of a
manageable size --- which is what the subdirectories are for.
\end{cccaution}

If there is nothing to show at all, \ccprod{} says \msg{no matching files on
the card} and abandons the command.

\subsection{What happens when a workbook loads}

The header is checked before anything in memory is touched, so a file that is
not a \fname{.X16S}, or is a newer version than this program understands, is
rejected and your current work is untouched.

Past that point the workbook in memory is cleared and the file is read into it.
Formulas are compiled after the file has been closed, which is why a large
workbook pauses twice.

\begin{ccnote}
If a file turns out to be damaged \emph{after} the load has started, \ccprod{}
clears the workbook rather than leaving you with half of one. You get an empty
worksheet and a message, not a plausible-looking workbook missing its last
four hundred rows.
\end{ccnote}

\section{Naming files}
\index{file names}

\begin{ccsteps}
\item A name may be up to sixteen characters as far as CMDR-DOS is concerned.
The dialogue will let you type twenty-three.
\item \textbf{Capitals are safest.} \ccprod{} converts lower-case letters for
the disk system automatically, and converts them back in the file list, so
lower case works --- but capitals are the range where the machine's character
set and the program's agree without translation, and they are what the built-in
files use.
\item \textbf{No extension is ever added.} If you want \fname{.X16S} on the end
of the name, type it.
\item An empty name cancels the command; it is not an error.
\end{ccsteps}

\section{Where files are read and written}
\index{device number}

\ccprod{} uses device 8 for everything, and there is no way to change that from
the program.

Everything is relative to the directory \ccprod{} was started in --- under the
emulator, the one named by \lit{-fsroot}. Two things follow, and they are worth
keeping straight:

\begin{ccsteps}
\item \textbf{\menupath{Open} always starts at the top.} Browsing into a
subdirectory is not remembered: the next \menupath{Open} or \menupath{Import}
begins at the starting directory again.
\item \textbf{But the path travels with the workbook.} A workbook opened from
\lit{ACCOUNTS} is remembered as \lit{ACCOUNTS/BUDGET.X16S}, so \key{F4}
\menupath{Save} writes it back where it came from.
\end{ccsteps}

\begin{cccaution}
\menupath{Save as} and \menupath{Export} ask for a name rather than showing the
list, and \textbf{that name is relative to the starting directory}, not to
wherever you last browsed. To write into a subdirectory, type the path:
\lit{ACCOUNTS/BUDGET.X16S}.
\end{cccaution}

\section{The workbook name on screen}

Once a workbook has a name, that name appears on the tab line, after the last
worksheet tab, for as long as there is room on the line for it. It is the only
place the current file name is shown.

\section{What can go wrong}

A failed file command puts up a box titled with the command and the word
\msg{failed} --- \msg{Save failed}, \msg{Open failed} --- and one line saying
why. The full list of those lines is in Chapter~\ref{ch:messages}; these are the ones you will
actually see.

\begin{cctable}{Message}{Means}{1.8in}{3.02in}
\msg{Disk error} & The card is full, write-protected, or not there. \\
\msg{File not found} & The name does not exist. From \menupath{Open} this
usually means the file was deleted between the list being built and your
choosing it. \\
\msg{Damaged or unrecognised file} & Not a \fname{.X16S} file, or one written
by a later version of \ccprod{} than this. \\
\msg{Checksum mismatch} & The file is a \fname{.X16S} but its contents do not
match its own checksum. Something has corrupted it. \\
\msg{Out of memory} & The workbook does not fit in this machine's banked RAM. \\
\msg{Resource limit reached} & The workbook is within memory but past one of
the fixed limits --- more than 128 styles, more than sixteen worksheets, more
than 8,192 distinct pieces of text. See Appendix~\ref{app:limits}. \\
\end{cctable}
